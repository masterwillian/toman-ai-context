# Memory Update Policy

Add information here only when it is likely to remain useful across future tasks.

Good candidates:
- confirmed architecture decisions;
- recurring environment constraints;
- stable workflow preferences;
- verified project invariants;
- recurring failure modes and their root causes.

Do not add:
- passwords or tokens;
- temporary status updates;
- unverified guesses;
- raw chat transcripts;
- private personal details unrelated to the work.

When current evidence contradicts stored context, update the stored context rather than forcing reality to match memory.
